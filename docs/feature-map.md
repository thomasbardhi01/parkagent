# Feature map

One row per product feature: where it starts, where its code lives,
which guardrails bind it, what tests it, and whether it is live. Read
this before exploring the repo; when you change a feature, update its
row in the same PR. `scripts/check-feature-map.mjs` (CI, `city-neutral`
job) fails when a path here doesn't exist, when a `path:line` points
past the end of its file, or when a route or job is in no row.

The diagram is `docs/feature-map.mmd` (phone → routes → services →
providers, the money gate, and the `pending_parks` state machine).

**Columns.**
- **FR**: ids in `docs/functional-requirements.md`; "none" means no FR
  describes the feature (listed again under [No FR](#code-with-no-fr)).
- **Money/guardrails**: where caps (`policyFor`), CAS (a conditional
  `updateMany` / claim), DRY_RUN, consent (a tap, a token, the user in
  the loop) and arrival (phone at the car / away / back) are enforced.
- **Tests**: server `server/test/`, live `server/fr/`, iOS
  `ios/ParkAgentTests` / `ios/ParkAgentUITests` / `ios/ParkAgentReleaseTests`.
- **Scope**: `boston-path` is on the path a Boston street park takes,
  city-neutral code included; `garage-only`; `nyc-only`. Tooling rows
  are `—`.
- **Status**: `shipped` (merged; deploys on merge to main),
  `dry-run only` (moves money, and prod runs with DRY_RUN on), or
  `blocked by #N` (not live until that issue lands).

Line numbers are anchors as of the commit that last touched this file;
the check keeps them in range, not exact. Re-anchor when you touch a row.

## Money path (start, extend, stop, holds, Issuing)

Every path that would buy time or move money asks **one money gate**,
`moneyGate` (`server/src/services/moneyGate.ts:194`), with what it means
to do and who is acting (`Principal`, `server/src/services/principal.ts`):
a start (`runStart`, `server/src/routes/session.ts:198`), the walk-away
prompt (`server/src/services/pendingSession.ts:539`), `/parked`'s auto-pay
rule (`server/src/routes/parked.ts:211`), a manual extension
(`server/src/routes/session.ts:778`) and the worker's
(`server/src/jobs/extendTick.ts:324`), both again on the fresh row under
the extension lock (`server/src/services/sessions.ts:204`), a stop, the
assistant's confirm (`server/src/routes/assistant.ts:500`), and the three
funding moves (amount-only, `server/src/routes/card.ts:190`). The rules
live only there: per-stop and daily caps (`policyFor` + `spentToday`,
`server/src/services/moneyGate.ts:118`), max stay, the effective dry run,
the provider link, what the tap was shown, the phone's position for an
auto extension, and consent for an external agent
(`users.agents_may_act`, `server/src/services/moneyGate.ts:208`). Each
intent keeps the order its path refused in, so decision rows read as
before. `server/test/limitsScan.test.ts` fails a cap read anywhere else.
