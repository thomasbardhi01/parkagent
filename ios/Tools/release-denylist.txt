# What must never ship in a Release (TestFlight / App Store) binary, and
# what must. Read by BOTH ios/Tools/check-release-binary.sh (`strings` on
# the built app) and ParkAgentReleaseTests (a byte scan of its own host
# binary, running inside the Release build).
#
#   <text>        forbidden: a case-sensitive substring that must not appear
#   + <text>      required: must appear — proves the scan is reading the right
#                 binary, so a clean result can't come from scanning nothing
#   type N K      forbidden TYPE (ParkAgentReleaseTests looks it up in the
#                 Swift runtime by mangled name 9ParkAgent<len>N<K>; K is V
#                 struct, O enum, C class/actor). `+ type N K` must exist.
#                 ParkAgentTests proves every entry resolves in a Debug
#                 build, so a wrong name or kind can't pass vacuously.
#
# Blind spot: Swift stores string literals of 15 bytes or fewer INLINE in
# the instruction stream, not as C strings, so neither `strings` nor a byte
# scan can see short literals like "Simulate park" or "-uiTesting". Every
# entry here is therefore a type name (type metadata keeps it as a C
# string), a stored-property name (reflection metadata), or a literal of 16+
# bytes — debug UI is caught through its accessibility identifiers. The
# type check in ParkAgentReleaseTests covers the rest.
