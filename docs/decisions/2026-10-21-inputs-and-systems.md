# 2026-10-21: Inputs and systems map (before WS-4)

Status: **proposed** (D0 of the WS-4 batch, #238; revised after the
coordinator's review). Read-only: this record changes no code. It names
every raw input and what it is trusted for, every place one signal or
decision is computed twice, and what WS-4 must not add. Lines are anchors
at `bca4241`; #241 (open) moves some of them.

## 3. Delete list (D's scope; one owner each)

1. **Position**: `extendTick` drops `haversineM`, `headingFromDistances`, `FIX_MAX_AGE_MS` and the `at_car`/no-park fallback; it asks `pendingSession` (park row + `fixCountsFor` on the newest fix). So does #241's reader under the extension lock (`applyExtension`, `source === "auto"` → `phone_not_away`): the gate absorbs it, leaving one reader. A session with no park row is `unknown`. `location_fixes` gains `measuredAt` (additive) so the one classifier reads one clock.
2. **Max stay** in `moneyGate`; the four copies go, `extendTick` keeps only its margin as a gate input.
3. **Per-stop cap** in `moneyGate`; four copies go.
4. **Daily cap** in `moneyGate` over one `spentToday` (street + Link + Issuing captures, with #241's `dryRun` option); nine spend copies go, the Issuing-only sum with them. `card.ts:190, 335` and `providers.ts:419` are funding-move ceilings (amount only, not spend): the gate keeps an amount-only mode for them.
5. **Dry run**: the gate reads `effectiveDryRun()` once per money path; `/health` asks the policy service. Sites that only label a decision row keep the call.
6. **Provider usable** at the gate; `applyExtension` gets it by calling the gate.
7. **Token**: the assistant's, extended to bind the amount. E and F reuse it; nothing new is minted.
8. **Receipt bound** at the gate: `session.amountUsd` = min(receipt, shown), or refuse when they disagree (§5).
9. **Decisions**: `withDecisionLogging` stamps `actor` and `agent_key_id`; no second writer, the eight helpers call through it, and `actor` gets a DB default of `user` so the two bare-`prisma` scripts stay correct.

## 4. Do not build (WS-4)

- **No location input from an agent.** The phone is the only source of arrival; `advanceWalk` the only reader. `/agent/*` accepts no `lat/lng`, no `arrived`, no `left_car`; an agent key on `POST /assistant/message` has its `location` refused.
- **No new state for a plan.** A REST/MCP plan **is** an `AssistantPlan` row (the token already binds to it, `tools.ts:2634`); a street leg with `start: now` is a `pending_parks` row (`confirmed`, from the plan's spot) that the walk-away lifecycle completes, answered `pending_arrival`; garage legs go through `Itinerary` / `LinkSpendRequest`. No third table.
- **No second** token, gate, cap sum, dry-run read, auth resolver (`makeAuthenticate`), decision writer (`withDecisionLogging`), rate limiter (`services/rateLimit.ts`), or idempotency layer (`registerIdempotency` is app-wide on unsafe authed requests, `app.ts:287`; REST gets it free).
- **No amount from an agent.** The server prices every option; an agent names one and gets the price back, as the model does.
- **No consent beyond `users.agents_may_act`** (D), checked only for `actor: external_agent`.
- **No key shaped like the admin key**: scoped, per user, revocable, rate-limited.

## 5. Decided, and open questions (for the human)

Decided: **the daily cap binds under dry run on recorded dry-run spend** (founder, #226 2026-10-21; built in #241 as `spentToday(…, {dryRun})`, and from #244 the one sum the gate reads: the assistant's plan paths and its budget line count it too; only the Wallet's Today still counts real money alone). **Clock windows are 12 h** for `/parked`'s price clamp (what `ParkOutbox` can send) and ±5 min for a held park (#241); `measuredAt` gets the future bound the app already applies. **Reversibility decides dedicated tools** (founder, 2026-10-22): confirm, start, extend and stop stay typed, gated and logged, each its own capability behind the one gate; there is no generic action tool, ever.

Answered by an experiment, not a person: **which assistant scaffolding exists because a 2025 model needed it?** Candidates: `requestState` patching and `update_request`, the search state rebuilt from the transcript. D-1c runs the FR 40-assistant suite on `claude-sonnet-5-5` with strict tools and structured outputs (`output_config.format` where a tool's job is "return JSON") and that scaffolding stubbed out; a pass puts it on the delete list and D-1c deletes it, a failure records which cases needed it, in D-1c's body with the run's commit and seed.

1. **Agent keys: a separate `agent_keys` table (Issue E as written) or a row kind on the existing `users.api_key_hash` mechanism?** Separate: scopes, label, revoke and rate limit per key, no change to the admin path. Row kind: one resolver and one hash path, but the admin key's shape (unscoped, unrotated) is the thing not to copy.
2. **A start that failed after the pay click**: should the gate treat `afterPayClick` as "charged, unconfirmed" (park closed, no hold release, no second start) rather than unpaid?
3. **The receipt bound**: `min(receipt, shown)` records less than the provider may have charged; refusing on disagreement leaves a paid session `failed`. Which, and at what tolerance?
